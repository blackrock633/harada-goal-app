app (and the wider product ecosystem) has added. Researched 2026-10-19.

## 1. The central goal and the long-term goal form

- Method has five forms/tools: self-evaluation (33 questions), Long-Term Goal Form, Open Window 64,
  Routine Check Sheet, Daily Diary. Listed in a search snippet for a PCS Press / iSixSigma
  page [S1/S2 family]; the exact wording of the five-form list is from a snippet, moderate confidence.
- One central goal sits at the middle of the OW64 grid [S1, S3].
- A goal date matters "so that you can measure progress against that date"; sub-steps get
  incremental due dates [S1].
- The goal form asks the person to "consider the purpose behind the goal" and weigh its
  "tangible and intangible aspects" [S1]. Others (family, friends, colleagues, mentors) are
  consulted [S1].
- NOT FOUND in any fetched source: a formal 2x2 (self/others x tangible/intangible) grid.
  From background knowledge (unverified here) Harada's goal form does ask about the purpose of the
  goal for oneself and for others, tangible and intangible; treat the 2x2 as plausible but unconfirmed.
- Ohtani example: goal "be the No. 1 draft pick" at 8 teams, four years ahead [S3].

## 2. The eight surrounding elements

- Eight smaller goals/tasks surround the centre, each "believed to be required for the goal" [S1];
  "eight yearly support goals" in the Ohtani chart [S3].
- Ohtani's eight (as printed in S3): physical conditioning, mental strength, four pitching skills
  (control, sharpness, speed, trickery), character, and karma/luck. Other pages list slightly
  different names; chart contents are not a method rule.
- Naming varies by source: "elements", "pillars", "sub-goals", "tasks". No source fixes the term.

## 3. The 64 actions and the 9x9 layout

- Each of the eight elements gets eight smaller goals/actions; "the 64 steps give the template its
  name"; the chart has 81 boxes [S1]. S3 describes a 9x9 grid with eight daily behaviors around each
  support goal (the number 64 is implied, not stated).
- Arithmetic (derived, not sourced): 9x9 = 81 cells. 1 centre goal + 8 elements + 64 actions = 73
  cells hold meaningful content. In the 9x9 layout the 8 elements appear twice (once in the centre
  3x3 block around the goal, once as the centre of each outer 3x3 block), so 81 = 1 + 8 (ring) +
  8 (repeats at block centres) + 64 actions. Thus 72 non-central positions, of which 8 are repeats
  and 64 are unique actions. The "73" count is a count of distinct meaningful items, not of grid cells.
- The "64" in the name counts only the actions.

## 4. One-time tasks vs routines

- [S1]: OW64 is used to develop routines toward the long-term goal; the example shows five daily
  routines (study a technique, meditate, exercise). A search summary characterises the 64 cells as
  "mini-tasks and routines" (mixed).
- [S3]: the eight cells around each support goal are "daily behaviors" (e.g. pick up trash,
  clean room, respect umpires): routine-like, not one-off.
- NOT VERIFIED: any explicit rule that each OW64 cell must be tagged "task" or "routine", or that
  the method has a first-class one-time-task concept. From background knowledge, Bodek's book
  separates routines (repeated) from tasks (done once) when filling the chart, but this was not
  confirmed from a fetched source.

## 5. Planning vs execution

- Routine Check Sheet: daily checklist built from the 64 items; keep to "not more than ten"
  items; mark done as 1/0 or check [S1]. Its aim is to "facilitate the goal's achievement"
  and not block early progress [S1].
- Daily Diary: works like "a typical to-do list" that plans the day around the goal and tracks
  progress against the routine check sheet [S1].
- Flow (per S1/S2): goal -> OW64 -> pick routines -> check sheet -> daily diary -> daily review.
- NOT FOUND: a rolling adherence percentage, scheduling (weekly N times), or due-date mechanics
  for routines. The method's check sheet is a simple daily done/not-done.

## 6. Reflection and self-assessment

- Self-assessment: 33 descriptors/questions, each rated 1 to 10, used to find areas to improve [S1].
- Daily reflection: "at the end of each day, the individual can see what was accomplished and what
  still needs work" [S1]; "continuous self-monitoring ... assess progress, adjust, reflect" [S2].
- Core value is self-reliance (becoming skilled enough to be irreplaceable) [S1/S2 family].
- NOT FOUND: weekly reflection as a formal step, structured reflection fields, or plan
  "adjustment" logging. From background knowledge, Harada coaching includes mentor/coach feedback
  on diaries; unverified here.

## 8. Comparison with docs/DOMAIN_MODEL.md section 1

Matches (supported): central Goal with date; 8 x 8 structure; routine check sheet as daily
check; diary-like reflection; no gamification.

Divergences and overstatements:
1. "Long-Term Goal Form ... 4-quadrant Purpose" is stated as Harada fact. The self/others x
   tangible/intangible grid is not confirmed by fetched sources (S1 only says "tangible and
   intangible" and consulting others). Reword as "inspired by" or verify against Bodek's book.
2. "Open Window 64 -> Outcomes (<=8) x Actions (<=8)" is faithful in shape, but the method has
   exactly 8 and 64 (a full chart); the app allows fewer, which is fine as an adaptation. The
   9x9 visual with repeated element cells is not modelled; "73 meaningful cells" should be
   described as 1 + 8 + 64 distinct items.
3. `Action.kind = task | routine` presented as a Harada tool row. Sources describe OW64 items
   as routines/mini-tasks; a formal per-cell tag is not confirmed. Label as adaptation.
4. Routine Check Sheet maps well to done/not-done, but the app adds schedules (weekdays,
   weekly N), adherence over 28 days, streaks and due-today ranking. These are not method
   features. The method's suggested cap of ten routines on the sheet is not enforced.
5. "Daily Diary / self-reflection -> Reflection (daily or weekly)": the Daily Diary in sources
   is a daily to-do/plan tied to the check sheet. The app has no daily plan record; it only has
   reflection entries. Weekly reflection is an adaptation.
6. "Adjusting the plan -> GoalEvent history": no sourced equivalent; adaptation.
7. Outcome `measure` (target/current/unit), goal status lifecycle, on-track pacing: product
   additions. 33-question self-evaluation and mentor/others input are not represented.
8. The user journey ("Vision -> ... -> Adjustment") is the app's own framing, not Harada's.

Recommended action: before the next release, either obtain Bodek's book / Harada Education
Institute forms to confirm items 1, 3 and 5, or keep the DOMAIN_MODEL wording as "adapted from"
and mark the purpose grid and task/routine tag as product choices in docs/DECISIONS.md.
